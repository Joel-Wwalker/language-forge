# Installing toylang

`toylang` is a c_like programming language with dynamic typing and host_gc memory semantics. Source files use the `.toy` extension. The compiler transpiles your source to Python.

## Requirements

- Python **3.11 or newer**
- A terminal that can run `python` and `pip`

That's it. The runtime is plain Python; no external compiler needed.

## Install (one command)

From this directory:

```bash
pip install -e .
```

That installs `toylang` as a Python package **and** registers a `toylang` console command on your PATH.

To install into an isolated environment (recommended):

```bash
python -m venv .venv
. .venv/Scripts/activate          # Windows
. .venv/bin/activate              # macOS / Linux
pip install -e .
```

## Verify the install

```bash
toylang --help
```

You should see usage text. If you instead see "command not found", make sure your virtualenv is activated, or fall back to the module form:

```bash
python -m toylang.compile --help
```

## Run a program

Write `hello.toy` (see the README for syntax):

```
print("Hello, toylang!");
```

Compile and run:

```bash
toylang hello.toy              # writes hello.toy.out.py
python hello.toy.out.py                # runs it
```

Or pipeline both in one shot:

```bash
toylang hello.toy && python hello.toy.out.py
```

## Where things live

```
toylang/
├── README.md           — friendly intro + syntax tour
├── LANGUAGE.md         — full language reference
├── INSTALL.md          — this file
├── LICENSE             — MIT
├── pyproject.toml      — pip-installable package metadata
├── examples/           — sample programs you can run
├── tests/              — canonical test programs (must all pass)
└── (compiler source)   — lexer.py, parser.py, codegen.py, runtime.py, ...
```

## Run the canonical tests

```bash
cd tests
toylang hello_world.toy && python hello_world.toy.out.py
```

Each test program has an adjacent `<name>.expected_output.txt` you can diff against.

## Uninstall

```bash
pip uninstall toylang
```

## Bug?

This language was generated by [Language Forge](https://example.com/forge). Open the `resolved_spec.json` to see exactly which design choices the generator made. Each LLM call's prompt + response is logged under `.forge_log/` (if that directory was preserved when you received the package) — you can read those to understand why the generator made a particular call.
