Designer & vibe, persona, era, theme, bans, constraints Optional. Strong character changes per the EaC catalog.

Designer persona

The resolver consults this designer's values when filling gaps. Same options + different persona = visibly different language.

Era preset

Pre-vetted bundles of options that evoke a programming-language decade. Your explicit option choices always override the era.

Keyword theme

Replace the keyword set with a themed variant. Composes with the keyword overrides in the Advanced section.

Feature bans

Forbid specific constructs. The parser refuses them; tests adapt.

Hostile constraints (free-form)

Anything you want the resolver to honor. e.g. "every program must contain a recursive function", "no two keywords share a starting letter".

Natural-language phrasebook

Replace keywords with sentence templates. Programs read like prose. Pick a preset, or fill in your own. Use <name>, <value>, <cond>, <body>, <else>, <params>, <args> as slots.

Docs voice

How the generated README is written. Honesty rule: technical content stays accurate regardless of voice.

Advanced, customize keywords, operators, prompts, and tests Optional. Leave alone for sensible defaults.

Keyword overrides

Replace any built-in keyword with your own spelling. Leave blank to keep the default.

Operator overrides

Comma-separate the operators you want for each category. Leave blank to keep the defaults.

Design notes

Free-form descriptions of what makes your language unique. The resolver will incorporate these into design decisions.

Per-component instructions

High-priority notes injected into the LLM prompt for a specific component. Use for behavior the design notes can't capture.

Additional tests

User-supplied test pairs that the verifier must also pass. Use these to validate your custom features.
